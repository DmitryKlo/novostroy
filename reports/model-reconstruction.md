Воспроизведение из корня проекта:

```bash
rtk proxy .runtime/dev-env/bin/python -m sources.models.build
rtk proxy .runtime/dev-env/bin/python -m sources.models.audit data/models/models-v1-92dc659b5e75fa52
rtk proxy .runtime/dev-env/bin/python integration/check_model_routes.py
```

`build` выполняет полный детерминированный проход; повтор той же команды проверяет неизменяемый run и использует content-addressed `data/models/cache/geometry`. Отдельного incremental-флага нет. Атомарная публикация этого проверенного run уже выполнена командой `rtk proxy .runtime/dev-env/bin/python -m sources.models.publish models-v1-92dc659b5e75fa52 e729ac65bcf9b436ab3dfa4b8f76c5bda643c3c2bcf9cbc33e7a9c4f18c28c6b`; повторно публиковать его пользователю не требуется. Для **уже работающей управляемой пары** в обычном терминале того же компьютера и checkout нужна одна команда: `rtk python scripts/dev.py restart-api`. Она сама сверяет активный run через веб-прокси; затем открыть `http://localhost:5173/models?decision=rejected` либо тот же путь по LAN-адресу.
