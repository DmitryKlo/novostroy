# Sol-Max — раунд 1: адресная критика

Дата: 2026-10-09. Только обсуждение гипотез из [SW brief](sol_web_cache-brief.md) и [LL brief](luna_lod-brief.md), без чтения их 400 идей. Первичные документы в этом раунде повторно не открывались. Уровни доказательства нужно отмечать раздельно: **источник обнаружен → текст прочитан → файл получен → геометрия проверена → права на публикацию подтверждены**. Переход между уровнями нельзя подразумевать.

## Адресные возражения

**D-SM-01 → Sol web/cache, направление «два производных пакета из одного исходника».** Операционный провал: конвертер выпустит web и mobile LOD, но договор может разрешать только веб-показ или запрещать переработку/кэш. Тогда технически валидные файлы не могут быть опубликованы. Проверка: на одном добровольно переданном образце до конвертации заполнить матрицу `storage/derivative/web/iOS/CDN/expiry/revoke` и заставить ingest отказывать при пропуске любого нужного разрешения. Альтернатива: ограниченный внутренний geometry QA без публичного asset root; разрешённый проектный план отдельно от авторского фасада.

**D-SM-02 → Sol web/cache, направление «готовые модели из официальных viewer».** Операционный провал: публичная 3D-страница может не отдавать скачиваемый корпусный файл и не иметь правообладателя экспорта. Обработанный [source brief](report_sources-brief.md) сообщает: ПИК-страница при read-only проверке ответила 401, ФСК показала HTML/изображения, но ни GLB, ни размеры корпуса не извлечены. Проверка: в выборке десяти страниц считать отдельно обнаруженные viewer, установленного владельца, предложенный файл и письменные права. Альтернатива: использовать viewer только как контакт/версионную подсказку; переключить пилот на официальные планы и прямой запрос владельца.

**D-SM-03 → Luna LOD, направление «геопривязка плана и секционный профиль».** Операционный провал: индексированный PDF Тайнинской пока не был полностью открыт нашим инструментом; даже прочитанный лист может оказаться сканом с деформацией, а МСК/высотный датум — не задан. Точная модель на карте при этом была бы ложной. Проверка: получить разрешённый исходный лист, калибровать по двум независимым направлениям и третьей контрольной точке, записать остаток, единицы и высотную основу **до** выпуска меша. Альтернатива: хранить план в локальной системе как непозиционированный draft либо публиковать только текстовое утверждение о проекте без footprint.

## Свои идеи под защитой и пересмотр

- **Защищаю SM-Q2-100:** ingest должен явно разделять «получено/извлечено/разрешено/не доказано». Дешёвая проверка — один разрешённый GLB и один отрицательный fixture без лицензии; успешный результат — второй не проходит в public root, а у первого сохраняется воспроизводимый манифест.
- **Защищаю SM-Q4-041/042 как одну связку:** наблюдаемый котлован и проектный корпус — разные полигоны, даты и ошибки. Дешёвый тест — сопоставить один план с одним датированным наблюдением; если связь корпуса не подтверждена, оставить обе сущности несвязанными. Это убирает соблазн выдавать размеры выемки за размеры будущей башни.
- **Понижаю SM-Q1-033:** поиск в официальном Sketchfab-профиле может дать только презентационный вариант или generic asset; корпусная ревизия и права, вероятно, будут слабее, чем у прямого держателя BIM. Оставить редким discovery-каналом, не опорой пилота.

**Голос: A — гибрид** добровольно лицензированной готовой модели и измеримого документного LOD с разными метками качества. B («только готовые модели») может не дать покрытие, C («иллюстративный AI») нельзя выдавать за размеры/фасад конкретной новостройки. Это голос для дебатов, не решение о публичном слое или внедрении.
