# Локальные объекты и пешеходные маршруты: проверка 2026-10-10

Для двух типов подтверждённых точек основной карты добавлены три независимых слоя POI: метро, образование и медицина. Слои скрыты до выбора пользователем. Выбранная точка определяется непрозрачным `mappt_` ID из активных 10 реестровых и 756 OSM-точек; клиент не передаёт произвольные координаты. Локальный OSM-снимок 2026-10-08 даёт 276 станций метро, 2 121 школу, 2 881 детский сад и 1 848 объектов с тегом клиники после удаления дублей внутри категорий. Эти 7 126 записей не доказывают полноту Москвы, текущую работу или возможность посещения. Шесть площадок клиник сверены с официальной программой ОМС на 2026 год и точными OSM-идентичностями; у всех маркер из площади приблизительный. Исходники и границы обновления описаны в [кратком аудите](../docs/briefs/amenities-source-readiness.md).

Маршрут для выбранной точки возвращает максимум пять POI на слой. Кандидаты выбираются по **расстоянию по прямой**, затем для каждого пытается рассчитаться пешеходный путь по локальному графу. Это не пять кратчайших пеших маршрутов. В медицинском слое, если среди обычной пятёрки нет подтверждённой ОМС-площадки, пятая заменяется ближайшей из проверенных: `nearest_four_plus_nearest_verified_oms`. Она может находиться далеко, поэтому расстояние, время при успешном маршруте и особая политика выбора показываются явно. Более пяти клиник не выдаётся. При отсутствии действительной подтверждённой записи состояние `unavailable` означает недостаток данных, а не отсутствие бесплатной помощи. Участие организации в ОМС не гарантирует конкретную услугу или приём без направления. Маршруты всегда оценочные: входы жилых домов не подтверждены, контуры POI часто дают только представительную точку, а маршрут с привязкой к графу дальше 50 м отвергается без времени. Путь ограничен 512 координатами; живые перекрытия не отслеживаются.

[Независимая offline-проверка](../integration/check_nearby.py) прошла на активных данных и OpenAPI/JSON Schema: mapped точка вернула 15 кандидатов, все 15 с допустимым маршрутом; viewport 0,02° дал 22 маркера без маршрутов, при лимите 150. Синтетический тест сравнил поиск ближайших с полным перебором, а fake Valhalla с входными `trip.locations`, но фактическим концом линии дальше 50 м, получил `snap_exceeds_threshold` без времени. Проверены точные opaque IDs, группы/лимиты, неназванный источник, текущая ОМС-sidecar принадлежность, запрет шестой медицинской записи, 422/404, приватные weak ETag/304 на прямых routes. После первого запуска worker запрос занял 0,406 с, повторный 0,003 с в том же Python-процессе; это **не** сетевые задержки и не FPS. [Отдельный профиль](nearby-performance.md) измерил около 383,3 МиБ RSS worker вместе с `rtk` wrapper после загрузки графа, что требует проверки памяти на целевом хосте. Backend отдельно проверил полный in-process ASGI middleware для обоих путей: 200/304 с `private, max-age=0, must-revalidate`, неизвестный ID 404 `no-store`, источник-открытый режим `no-store`; релевантный набор backend — 41/41, локальный geodata worker — 6/6. Синтаксическая проверка Unity разобрала 13 C# файлов без ошибок, но Unity/iOS не собирались.

Web выполнил 39 unit-кейсов и production build PASS; финальные файлы `index-EX85z1fY.js` и `index-qD8ozMuk.css`. Статический review проверил скрытое начальное состояние, включение трёх слоёв при выборе точки, ограничение пяти записей, смену фильтра образования, отмену и сверку ID устаревших ответов, ограниченную viewport-загрузку и очистку маркеров/маршрутов. Найденное перекрытие панели нижней мобильной навигацией исправлено CSS; после этой правки сборка прошла повторно, браузерный вид не проверялся. Host API здесь не перезапускался, а browser/TCP и iPhone не проверялись из-за ограничения среды. Для уже управляемого локального сайта понадобится одна команда из обычного терминала того же компьютера: `rtk python scripts/dev.py restart-api`; затем открыть основную карту и выбрать точку. [Контракт v1.4](../contracts/IMPLEMENTATION-1.4.md) задаёт ответ и статусы, не превращая OSM-теги в подтверждённые городские реестры.
