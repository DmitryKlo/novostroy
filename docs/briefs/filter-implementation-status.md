# Статус пользовательских фильтров (read-only, 2026-10-10)

**Исторический baseline до внедрения реестровых фильтров и датированной видимости.** Последующий [отчёт по десяти замечаниям](../../reports/user10-regression.md) тоже относится к промежуточному EstateLine/OSM-снимку. Текущий developer-map содержит 1 163 записи издателей и 1 027 точек домов; числа «10 точек» и «639/1473» ниже не описывают текущий каталог.

Основание: пользовательский список передан root; полная матрица полей — [`docs/criteria/property.json`](../criteria/property.json), расширенный wire-registry — [`contracts/criteria_registry.json`](../../contracts/criteria_registry.json). **Схема/контрол не означает наличие данных.** `predicates` работают по фактам предложения и fail-closed: неизвестное, просроченное, конфликтное, неочищенное по правам или неполное покрытие не совпадает.

Активный экран [`RegistryApp.tsx`](../../web/src/RegistryApp.tsx) имеет текстовый поиск по name/address и фильтры status/kind с фасетами; соответствующие `/v1/registry/buildings` и `/v1/registry/map` принимают query/status/kind. При этом response уже несёт `floors` и handover-поля, которые можно фильтровать по данным, но фильтров пока нет. Квартирные фильтры находятся в отдельном `App.tsx`/`/v1/search` + `/v1/map`, а не в registry endpoints. `AdvancedFilters.tsx` рендерит критерии из `/v1/criteria`; generic предикаты не создают факты в source. Сначала добавить scope-aware фильтры на существующих registry fields; unit/social/environment/amenity фильтры оставить unknown до фактических разрешённых records.
