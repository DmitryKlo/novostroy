# City data brief: Moscow

## Verified source options

- [Overture building schema](https://docs.overturemaps.org/schema/reference/buildings/building/) defines `geometry` (Polygon/MultiPolygon footprint or roofprint), `id`, `version`, `sources[]`, `height` (meters), `num_floors`, `min_height`, `min_floor`, `has_parts`, `is_underground`, roof fields, facade color/material, and class/subtype. Most height/facade fields are optional; a footprint plus height supports massing, not a surveyed architectural model. The [official area-download guide](https://docs.overturemaps.org/getting-data/) uses the Overture Python client with a bbox and says it transfers only matching GeoParquet data. The release catalog is STAC-backed and the client resolves the current release; pin the resolved release for reproducibility.
- The Overture [attribution/licensing page](https://docs.overturemaps.org/attribution/) lists the Buildings theme as ODbL and lists upstream sources including OpenStreetMap (ODbL), Esri Community Maps (CC BY 4.0), Microsoft Global ML Building Footprints (ODbL), and Google Open Buildings (CC BY 4.0). Preserve Overture `sources[]`, release, and required attribution. Review upstream obligations for redistribution/derived databases; do not assume all Overture themes share one license.
- [Geofabrik Central Federal District](https://download.geofabrik.de/russia/central-fed-district.html) provides regional OSM extracts (PBF and GIS packages). The regional file is large and covers far beyond Moscow, so it is not the preferred bounded sample. Geofabrik distributes OSM data; attribute © OpenStreetMap contributors and comply with [ODbL](https://www.openstreetmap.org/copyright). The extract page exposes the current snapshot/checksum; record those observed values when downloading, never substitute today's date for the data timestamp.
- [Overpass public-instance guidance](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) describes a shared resource. Use only for a single small bbox/sample or manual audit, with timeout/size bounds and a pause; do not use it for bulk Moscow extraction. Use a regional extract or Overture's bbox client for city-scale work.

## Recommended pipeline

Keep an immutable, bounded source export and a manifest with source URL/release or OSM replication timestamp, access time, license/attribution, bbox, byte count, SHA-256, and tool version. Normalize to GeoParquet (WGS84 lon/lat geometry, stable source ID/version, original `sources[]`, height/floor/roof fields nullable, explicit `height_source` and confidence); validate/repair geometry only in a derived copy. For topology/area calculations use a documented projected CRS; do not silently reinterpret missing heights or invent floor heights. Retain raw and normalized geometries. A pinned Overture release and OSM boundary-clipped Moscow dataset now exist; counts and hashes are in `docs/sources/city.md` and adjacent manifests.

For city context, build terrain/ground heights and city/administrative contours from separately licensed sources; footprints alone have no ground elevation. For coarse buildings, triangulate/extrude each footprint into a simple closed mesh, use known `height` or a clearly marked fallback policy, and preserve source IDs as feature metadata. Export glTF 2.0 GLB, then package spatially partitioned, bounded tiles as 3D Tiles 1.1 with GLB content and per-feature IDs/properties. Keep a source-to-tile index so updates can rebuild affected tiles. Confirm ellipsoid/vertical datum and local-to-ECEF transform before combining terrain and buildings.

## Blockers / limits

- Overture and OSM footprints/heights are not confirmed detailed models for any residential complex. They do not guarantee facade dimensions, windows, materials, ground elevation, completeness, or construction status.
- Detailed ЖК facades directly on the map require licensed project/BIM/CAD models or a licensed photogrammetry/3D source, source-specific usage rights, and a match between model and ЖК/building identity. No key or model source is confirmed yet.
- Current bounded run uses OSM relation 102269 (mapping boundary, not legal verification), Overture release `2026-09-23.1`, and a bbox envelope clipped to that polygon. It produced 564,031 valid building footprints; this does not prove source completeness or full coverage. Moscow Oblast is excluded by the mask.
- A rendered facade from a footprint extrusion is synthetic massing and must be labeled as such. Apartment floor slices are a later product layer, not derivable from these public footprints.

## Map-only render-height estimate

- Source facts stay immutable. Runtime priority: positive source height attribute → positive floors × 3 m → estimated overlay → 15 m renderer fallback. The source heights are OSM-provided attributes, not independently surveyed values. No apartment fields are changed.
- On the clipped 564,031-footprint source, only 59 of 440,304 rows without both height and floors passed the 35 m local shape/absolute-size gates. These are explicitly `estimated`, not observed; each row has donor IDs, donor height attributes, thresholds, and a heuristic confidence label. There were no exact canonical-geometry duplicate donors.
- Deterministic calibration: 90/911 similar-footprint matches, MAE 0.411 m, median abs error 0 m, P90 1 m, zero errors >10 m. Independent ID-bucket test: 52/862 matches, MAE 0.404 m, median 0 m, P90 2 m, zero errors >10 m. The 15 m fallback on those matched rows had MAE 10.007 m and 9.769 m, respectively.
- A one-off 250 m radius increased calibration coverage to 359/911 but introduced seven absolute errors >10 m, including a 6 m target assigned 220 m from a distant null-class donor. It was rejected; the production overlay stays at 35 m.
