# Ground map runtime: v7 readiness and layering

## Finding

The current v7 path has no full flat map phase. `MapView` creates a Cesium viewer with `baseLayer: false`, an opaque WebGL context (`alpha: false`), and matching solid globe/background colors. The map shell contains only the Cesium host. Its apparent “ground” therefore comes from Cesium’s neutral fill and the 3D tilesets; there is no independent streets/parks/water/footprints layer that can remain visible while buildings load (`web/src/MapView.tsx:48-64,252-257`).

The v7 manifest explicitly calls its first LOD “rasterized flat source footprint silhouettes”; it caps raster dimensions at 512 px and uses a 4-cell surface grid. Those silhouettes are GLB 3D Tiles content, not a complete cartographic base (`assets/public-citywide-v7/tileset.json:6-19,57-68`). Roads, parks and water are also entries in the Cesium `Tileset` list, not a separate always-on 2D renderer (`web/src/api.ts:43-44`). This explains why the current first view reads as sparse symbolic shapes rather than a flat city map.

## Why current readiness can skip or lose the visible stage

`Cesium3DTileset.fromUrl()` awaits the tileset JSON and metadata before returning; `MapView` then adds the object to `scene.primitives`. The `loadedTiles` UI count increments at that point, so it reports created tileset objects, not drawn tile content (`MapView.tsx:177-197`; installed Cesium `Build/CesiumUnminified/Cesium.js:195836-195849`).

Cesium documents `tilesLoaded` as “all tiles that meet the screen space error this frame” for “this view” (`Cesium.js:195035-195048`). In the installed implementation, `allTilesLoaded` fires after render only when pending requests, processing and attempted requests are zero **and** progress changed (`Cesium.js:196560-196588`). It is a settlement signal for the current view/SSE, not proof that the viewport has complete ground coverage or that a useful flat map was painted. `initialTilesLoaded` fires once per tileset. `MapView` listens to `allTilesLoaded` only; it does not subscribe to `tileVisible` or `tileFailed`, so nested region/GLB failures can leave holes without the current root-JSON error path reporting them (`MapView.tsx:188-200`; Cesium events declared at `194787-194793`).

The existing v7 “stage” switches the city tileset from coarse SSE to SSE 24 after `allTilesLoaded`. At the initial 5.2 km camera height the coarse formula is about 1,212; the automatic first flight moves to 800 m, where it caps at 1,500. This only selects coarser 3D tile content; it cannot produce a streets-and-parks map.

There is also a movement race. `moveStart` clears `silhouetteReady` and raises SSE to the coarse value. Every `camera.changed` while moving clears readiness again and recalculates coarse SSE. `moveEnd` requests detail only if the flag is still true (`MapView.tsx:215-220`). If the load event lands during motion, it sets the flag but declines the detail switch; a later `camera.changed` can clear it, leaving `moveEnd` with nothing to act on. If no later load-progress transition occurs, detail may remain at coarse SSE. Even without that race, repeated SSE changes select coarser parent content while moving, so loaded detail may disappear from the rendered frame without being evicted from cache. The `REPLACE` hierarchy can make that quality change especially visible.

Filters do not recreate the viewer, but `runSearch` fetches a filtered map and passes a new `MapData` object into `MapView` (`web/src/App.tsx:96-119`). The reconciliation keeps tilesets whose URLs still match, turns others off, and retains only up to three dormant entries; older/non-retainable tilesets are removed and can be fetched again when needed (`web/src/MapView.tsx:161-176`; `web/src/tileCache.ts`). On a hidden tab/mobile results panel, the viewer loop is paused rather than destroyed. However, the `[data, visible]` effect cleanup marks in-flight `fromUrl` work cancelled; if it resolves while hidden, the new tileset is destroyed and resume can request that URL again (`MapView.tsx:132-148,177-184,209-210`). Already-added tilesets remain in the map cache. Thus tab changes alone should not imply a full map reset, but pending loads and filtered-out layers can repeat.

## Recommended ground-first contract

Provide a permanent local 2D ground source covering the current viewport with readable building footprints, roads, parks and water. Keep it mounted and visible before, during and after all 3D loading. It must be an accurate, independently versioned source, not the v7 low-resolution silhouette layer. Keep the precise flat footprints visible under extrusions; do not add the old v7 silhouettes on top of that base. The 3D city layer should be an overlay whose loading, LOD replacement and failures cannot hide the base.

An independent DOM/canvas map under Cesium requires changing the current opaque canvas setup: enable WebGL alpha and transparent Cesium clear/globe rendering, then synchronize camera center, scale and bearing. An alternative is a distinct local 2D imagery/ground layer in the same Cesium scene; it must still be independently ready and never be gated by 3D tiles. No network imagery is needed for this design.

Use event-driven readiness tied to a camera epoch, not a delay:

1. **Ground ready:** the 2D source/style is usable; the renderer confirms that footprints and the available roads/parks/water are actually represented in the current viewport; then the same renderer reports a completed frame for the current camera epoch. Use a rendered-feature query or deterministic visible-content/pixel coverage check after that frame, not just source feature counts, tile JSON, or a generic `postRender`. Keep the ground visible even if coverage is degraded; report missing source coverage separately.
2. **3D coarse visible:** for the current camera epoch, observe actual relevant city content selected for rendering (`tileVisible`, filtered by the expected source/content and viewport coverage), then wait for that frame’s `scene.postRender`. This proves a render pass completed after visible content was selected; it does not replace the ground readiness check.
3. **3D detail visible:** after `moveEnd`, accept current-epoch visible detail content and its completed frame before reporting detail readiness. `allTilesLoaded` may supplement this as queue-settled telemetry, never as the visibility gate. Listen to `tileFailed`; retain ground and report a degraded 3D state instead of waiting indefinitely. Keep `scene.renderError` as the separate renderer-level failure signal.

On `moveStart`, increment the camera epoch but keep the ground, already visible detail and current SSE. Let Cesium request newly visible tiles progressively and retain its `REPLACE` parent fallback while children load. Do not downgrade the entire tileset on every `camera.changed`; only update readiness for the new epoch. After `moveEnd`, request a render and reconcile coverage for that view. On hidden/resume, preserve the ground and completed tiles, resize and `requestRender`; avoid destroying pending root loads or deduplicate in-flight loads by URL. Keep the existing bounded Cesium cache policy and treat it as separate from storage for local ground assets.
