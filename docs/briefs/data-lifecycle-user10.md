## Update and cleanup boundary

Collection supports conditional fetch/no-op and immutable snapshots; its checkpoint is latest-only, so old snapshots accumulate. Model/asset builds create versioned output and atomically switch a manifest/pointer; repeated identical model inputs reuse their content-addressed run/cache. There is no general asset, source-snapshot, model-cache, or release garbage collector. Deployment verifies every release file against a SHA manifest, retains previous state for rollback, and documents that release/runtime directories are not deleted. `data/` and `assets/` are git-ignored, which keeps generated data out of Git but does not limit disk growth.

For a future cleaner, derive references from `assets/manifest.json`, `data/models/active.json`, each release manifest, and the external deployment state. Keep active and rollback releases, current and compatibility URL roots, source snapshots/manifests and rights/attribution evidence. Any collector should first emit a dry-run with exact paths, hashes, bytes, reference reasons, and a lock; prune only after a reviewed cache-expiry/rollback boundary. Do not use `current-only` for an update to an existing origin; the deploy gate requires `full-compat` when replacing a recorded release.
