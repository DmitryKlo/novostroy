# CIAN listings, prices and media: access brief

Reviewed 2026-10-10 from local source documentation and official CIAN pages. This is an access and rights assessment, not authorization to ingest CIAN data.

## What the public pages expose

The local property inventory currently covers authorized developer YRL/XML files and local bnMAP JSON responses; there is no CIAN adapter or CIAN offer snapshot. The source review also records no current unit-level price source with explicit public rehosting rights. See [`docs/sources/property.md`](../sources/property.md) and [`docs/briefs/property.md`](property.md).

CIAN's public Moscow new-build catalog and project pages expose project names/addresses, corps, delivery dates, room-type ranges, price and price-per-square-metre ranges, plan counts and images. A project plans page can also show an explicit information-update date: the reviewed MУЗА page stated “Информация о ценах и наличии обновлена 25.08.2026” and gave 1–4-room ranges by size and total price. On 2026-10-10 that embedded project snapshot was already 46 days old, so page presence is not proof of current stock. [CIAN new-build catalog](https://www.cian.ru/novostroyki/), [plans catalog](https://www.cian.ru/novostrojki/planirovki-zhk/), [MУЗА plans page](https://zhk-muza-i.cian.ru/planirovki/).

The filtered CIAN offer page for the same project exposed individual asking rows: source offer URL/ID, room count, price in RUB, price per square metre, area, floor/total floors, building corps/section, project/address and handover. The page also exposed project media and a “Планировка” / “План этажа” choice. In the captured example, 19 offers were listed and one row showed 44,129,320 ₽ for 41.20 m² on floor 4/20, corps 1, section 1. Treat each as a dated asking ad; an active or “online booking” ad does not itself guarantee that the apartment can still be bought. Project pages themselves tell users to confirm current price and availability. [filtered MУЗА offer results](https://www.cian.ru/cat.php?deal_type=sale&engine_version=2&from_developer=1&newobject%5B0%5D=5750446&object_type%5B0%5D=2&offer_type=flat&room1=1).

Media types visible on offer/project pages include apartment-layout images, “План этажа”, gallery photos, video/3D-tour links, project-card imagery and dated construction-progress photos (one page labels the progress gallery as official-developer photos). The publisher-side XML spec explicitly names `LayoutPhoto` (`FullUrl`, `IsDefault`) and `Photos`; it says CIAN may supply a plan from its own building database when one is omitted. I found no documented outbound field for a separate floor-plan image or a typed facade-render asset. The XML spec is for submitting an advertiser's feed to CIAN, not an export API for our app. It also requires feed publishers to avoid third-party photos, but does not grant us a license to copy images out of CIAN. Keep media rights separate from factual offer fields. [CIAN XML import requirements](https://www.cian.ru/xml_import/doc/), [example dated construction-progress page](https://zhk-muza-i.cian.ru/hod-stroitelstva/).

## Official access and rights boundary

The current CIAN site rules make use of the site subject to its agreement. The indexed official text says users must use the interfaces CIAN provides unless access is expressly authorized by a separate agreement; it also disallows unapproved automated programs for site access and, without CIAN's agreement, extracting, copying, distributing or otherwise using materials from the CIAN database. The API's own terms require an account-specific key requested from `import@cian.ru`, allow CIAN to refuse access, restrict use to the site's subject matter, and prohibit automated API scripts for collecting/copying/distributing data without prior permission. [Site rules](https://www.cian.ru/legal-documents/pravila_polzovaniya_sajtom_cian_0/), [API terms](https://www.cian.ru/legal-documents/usloviya_ispolzovaniya_servisa_api_0), [API documentation](https://public-api.cian.ru/docs/latest).

The documented API methods reviewed are account/agency-oriented (for example, listing “my offers” and retrieving offer details by IDs); I found no documented public endpoint for searching and exporting the whole Moscow new-build inventory. Ask CIAN to confirm whether a separate partner/licensing route exists for this use and to state allowed fields, volume/frequency, retained history, display/rehosting, and photo/plan rights. Do not reuse a key issued for another agency or bypass authentication/technical controls.

Direct web-reader fetches of `www.cian.ru/robots.txt`, the legal rules URL, the XML documentation URL and several pages returned HTTP 403; some offer URLs also returned cache miss. The plans subdomain and a filtered offer page did render in the read-only web viewer. Thus this review did **not** verify robots directives or a stable machine-readable route; the 403/cache misses are access observations, not evidence that all CIAN pages are inaccessible.

## Feasible integration path

1. Prefer a written CIAN partner/data agreement or an API/feed expressly authorizing our account to ingest third-party new-build offer rows and specifying price freshness, offer status, storage, public display, plan/floor-plan images and facade/render rights. Keep the CIAN key outside source control and logs. The existing adapters can be extended to read an authorized local JSON/XML export; there is no authorized live pull configured now.
2. If CIAN does not grant this scope, request developer-owned YRL/XML/API feeds directly from developers with field and media permissions. The existing local YRL adapter already handles dated asking prices and plan/photo URLs from authorized files.
3. Without either authorization, keep CIAN as an outbound link/reference for a user to open at the source. Do not batch-fetch public HTML, extract the database, download/rehost plan or facade images, or infer `available=true`. A saved HTML file is still CIAN material; local parsing does not create a display or redistribution license. It could only be considered for a bounded, rights-approved internal audit with a captured source URL and timestamp.

If a permissioned export arrives, normalize one `offer` per source listing ID. Preserve the source ID/URL, capture `observed_at`, publisher update time if supplied, total asking RUB and per-m² basis separately, room count, total/living/kitchen area, floor/total floors, corpus/section, project/building link, handover claim, and raw source fields. Use `availability=unknown` unless the authorized source provides a defined availability state. Store media candidates as typed references (`apartment_plan`, `floor_plan`, `project_facade`, `gallery`, `construction_progress`) with publisher, source URL, date, and independent `rights_status`; do not collapse project-level price ranges into apartment offers.
