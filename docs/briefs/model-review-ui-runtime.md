# UI/API runtime для оценки моделей и отклонённых кандидатов

## Текущие entrypoint’ы и API

Веб-клиент — один React entrypoint: `main.tsx → App.tsx`. `App` запрашивает `GET /v1/health` и без URL-router выбирает `RegistryApp`, если `catalog_view=building_registry`/registry включён, иначе legacy-каталог. В `RegistryApp` сейчас две локальные вкладки: «Каталог» и «Данные». Глубоких URL для экранов нет.

Экран реестра загружает параллельно `GET /v1/registry/buildings` и `GET /v1/registry/map`, проверяет совпадение dataset/snapshot, листает список страницами по 48 и повторно проверяет снимок при догрузке. Фильтры — поиск, статус выгрузки и вид здания. Карточки показывают имя, адрес, исходный статус/срок, этажность, дату и подтверждённость геоточки. Детальная запись и карта доступны через `/v1/registry/buildings/{registry_id}` и `/v1/registry/map`. Сейчас нет endpoint, TS-типа или UI для оценки 3D-кандидатов, статуса проверки модели или причины отказа; существующий `status` — статус здания из выгрузки, не решение модельного QA. Реестр также не гарантирует юридический ID корпуса: его публичный ID — непрозрачный хэш.

## UI, mobile и кэш карты

Каталог использует responsive layout и нижний переключатель «Здания/Карта» на узком экране; «Данные» — отдельный полноэкранный dashboard с возвратом в каталог. Это готовый UI-паттерн для отдельной вкладки/экрана «Модели»: список кандидатов с состоянием, фильтром «отклонённые» и заметной строкой причины. На телефоне нельзя полагаться только на маркеры карты: часть записей без подтверждённой точки остаётся лишь в списке.

Чтобы экран оценки не сбрасывал сцену, сохранять mounted `MapView` при переключении вкладок и скрывать его через существующий `visible=false`. Он держит Viewer, ограниченную adaptiveQuality-пробу и тайловый кэш; скрытая карта не рендерит, а до трёх неактивных tileset могут оставаться в кэше. Условный unmount `MapView` при выборе нового экрана уничтожит этот выигрыш и вызовет повторную загрузку. Сам список отказов не должен инициировать 3D-загрузки.

## Контракты, причины и источники

В backend есть endpoints каталога и building registry, но нет endpoint для review кандидатов. Источники в публичном payload по умолчанию скрыты: `NOVOSTROY_EXPOSE_SOURCES=1` считывается при старте сервера; request не может включить disclosure. Для публичной причины отказа не следует передавать сырую provenance, путь к файлу, внутреннюю ошибку или URL. Нужны устойчивый `reason_code` и отдельный безопасный русский `reason_text`, подготовленный backend; QA-ошибка загрузки, «не оценено», «не найден asset» и отклонение после проверки должны оставаться разными состояниями.

Не расширять `RegistryBuilding.status` под решение о модели. Предпочтительна отдельная версионируемая сущность/endpoint оценки кандидатов с candidate ID, ссылкой на registry snapshot/запись, evaluation snapshot, версией политики и датой. Список должен поддерживать пагинацию и серверный фильтр состояния, чтобы экран не загружал весь каталог. Открытый путь кандидата не доказывает совпадение с юридическим корпусом: link/confidence/неизвестное сопоставление должны быть явными.

При добавлении полей согласованно обновить `contracts/schemas.json`, `contracts/openapi.json`, контрактную документацию, backend, TS-типы/API, тесты и mobile контракт/проверки. Web сейчас не типизирует несколько уже контрактных registry-полей срока сдачи; не стоит копировать это расхождение в новых полях. Unity-клиент пока явно объявляет registry несовместимым и показывает сообщение; новый режим должен остаться явно безопасным или получить согласованную DTO/проверку, а не молча интерпретировать статус. Снимки источника и оценок нужно сверять независимо.

## Сборка и preview

Vite `dev` и `preview` слушают порт 5173, проксируют `/v1` и `/assets` на FastAPI:8000. `scripts/dev.py start --preview` проверяет локальные tilesets, при необходимости собирает web bundle, затем запускает managed API и Vite и сверяет health/публичные tileset-манифесты. Catalog view зависит от валидного локального импорта и режима; demo bundle сам по себе не доказывает наличие оценочных кандидатов. Read-only `scripts/dev.py status` сообщил `api: stopped (pid 634991)`, `web: stopped (pid 635317)`. Лайв HTTP/preview не запускался и не проверялся; unmanaged listener этим статусом не исключён.

Практический риск интеграции — смешать исходное покрытие зданий с покрытием модельной оценки. UI должен показывать denominator «найденные записи / оценённые / ожидают / отклонены», snapshot и датировку; «отклонён» должен сопровождаться человеческой причиной, а отсутствие результата не превращаться в отказ или в нулевой quality score.
