# Офлайн-сверка предложений застройщиков и объектов карты

Текущий локальный вход: `.runtime/research/developer-harvest/index.html`. Он ведёт к закрытому review, проверке 621 адреса, CSV/JSONL и переносимому ZIP; публичный сайт не менялся. Итоговый source delivery `developer-delivery-919ca9ca87c416f4` содержит 75 721 ID квартир по всем территориальным категориям, 14 969 строк в строгом московском срезе и отдельные 31 663 пространственных кандидата без подтверждённого адреса. Источник не доказывает текущую доступность этих квартир. Дополнительные Level/Etalon/AFI/Donstroy наблюдения вынесены отдельно и не прибавляются к этим числам.

Review `developer-review-f707dc39e905ad8a` зафиксировал 520 source-owned групп, 48 принятых проектных связей с 43 локальными записями и 30 групп ЖК с локальными членами. В десяти группах несколько локальных target ID, четыре межисточниковых алиаса проверены отдельно. Связей с индивидуальным корпусом или контуром — ноль. Исследование адресов `search-evidence-49919a92af3fcb4e` завершило все 621/621 исходных активных задач, учитывая 812 просмотренных страниц и общий лимит пять на адрес. Найденная проектная площадка не становится доказательством корпуса; пять дополнительных решений по Бруснике остаются review до точной первичной связи publisher ID с целевым адресом/кадастром.

Повторяемая команда для этого review:

```bash
rtk proxy .runtime/dev-env/bin/python -m sources.property.developer_matching \
  --harvest-manifest .runtime/research/developer-harvest/deliveries/developer-delivery-919ca9ca87c416f4/manifest.json \
  --claims .runtime/research/developer-harvest/search_claims.json \
  --manual-project-links .runtime/research/developer-harvest/matching/manual_project_links_2d783a91089f1a25.jsonl \
  --site-adjudication .runtime/research/developer-harvest/matching/project_adjudication_aggregator_tail_a_results.jsonl \
  --site-adjudication .runtime/research/developer-harvest/matching/project_adjudication_aggregator_tail_b_results.jsonl
```

Далее описан сам алгоритм; примеры из ранней стадии не расширяют текущие числа или статус публикации.

`sources/property/developer_matching.py` читает только проверенные локальные JSONL из манифеста harvest и зафиксированный список EstateLine/OSM targets. Скрипт не делает сетевых запросов и не меняет каталог, цены, координаты, модели или публичные группы. Вывод хранится в `.runtime/research/developer-harvest/matching/developer-review-<hash>/` с SHA-256 каждого файла и статусом `private_review_only`. Время локального наблюдения страницы не заменяет дату обновления предложения; права на цены/изображения не повышаются из `unknown` до `cleared`.

`units.jsonl` различает явный ID квартиры издателя от page-local наблюдения. При точном ID квартиры и точном ID проекта связь квартира→проект может быть принята **внутри одного источника**. `projects.jsonl` хранит отдельные проектные утверждения. `groups.jsonl` группирует только по паре `(source_group, source_project_id)`; для Proplanirovki группа помечена как `third_party_aggregator`, а не как официальная группа девелопера. Это само по себе не связывает проект с картографическим контуром. `project_matches.jsonl` отдельно связывает проект с локальным адресом: автоматически по уникальному полному адресу издателя или после отдельной закреплённой агентской проверки проектной площадки. Такая связь имеет scope `project_address_only`: она не подтверждает корпус, геометрию, этажность или текущий статус. Адрес стороннего каталога без такой отдельной проверки остаётся `review`. `building_matches.jsonl` содержит более строгую отдельную сверку корпуса с локальной записью: корпус/строение/дом не взаимозаменяются, участок или владение не становятся адресом готового дома, неоднозначные совпадения остаются `review`. Автоматически принятая корпусная связь требует единственного совместимого полного адреса корпуса с типизированными компонентами в обоих источниках либо одного явного building-scoped ID в обоих. В текущих EstateLine данных нет канонического ID ЖК, поэтому близость и одинаковое название не дают кросс-источниковую связь.

Частный файл `.runtime/research/developer-harvest/matching/manual_project_links.jsonl` хранит рецензию агента (`reviewer_kind=agent`), а не человеческое подтверждение или право публикации. Проектная связь принимается при точном кадастровом участке в локальной записи и зафиксированном официальном документе, названии проекта и единственном source-owned ID проекта в harvest; URL, хеш и исследовательский файл проверяются. Корпус, контур и текущий строительный статус остаются отдельными. Два проверенных target ID для ЖК «Прокшино» служат первым локальным примером.

`report.html`, `REPORT.md`, TSV, CSV и JSONL позволяют проверить решения и причины с исходными source/target IDs и ссылками. HTML работает локально без сервера, поддерживает поиск и показывает максимум 100 строк на таблицу одновременно; полный набор остаётся в JSONL/TSV. Он экранирует данные источников и использует только безопасные HTTPS-ссылки; ячейки CSV/TSV защищены от формул. Манифест сверки и отдельная схема `contracts/developer-matching.schema.json` фиксируют состав. Повтор с теми же входными байтами возвращает тот же каталог без перезаписи.

Поисковая очередь — отдельный ручной процесс. `search_tasks.jsonl` хранит дедуплицированные адресные запросы со всеми исходными target IDs. Сырой адрес стройплощадки или значимое название ЖК с Москвой допустимы **только как запрос**, даже если строгий адресный парсер не допускает автоматическую связь. `search_insufficient_input.jsonl` содержит действительно непригодные или нежилые записи; архивные адреса остаются в очереди со статусом `deferred_archived` и не входят в первый батч. `search_shard_<worker>.jsonl` делит активные задачи между `report_sources`, `luna_cache`, `luna_clinics`; хвостовые пачки `address_tail_a_batch70.jsonl` и `address_tail_b_batch70.jsonl` закреплены отдельно в `search_claims.json`. `search_first30_<worker>.jsonl` даёт ближайший батч. Для каждой задачи максимум пять просмотренных страниц; `consulted_pages=[]` в исходной очереди означает, что поиск не проводился. Исследователь обязан сохранять URL, способ/дату доступа, область утверждения (проект/корпус/квартира) и исход `resolved/rejected/unresolved`; найденная ссылка не становится автоматическим join.

Результаты исследователей можно отдельно закрепить через `write_search_evidence(...)`: индекс проверяет typed target ID, принадлежность очереди, HTTPS URL, дату и **общий** предел пяти просмотренных страниц на адрес в нескольких файлах; он не повышает ручное наблюдение до продуктовой связи. Покрытие из `REPORT.md` — только покрытие фактически собранных каталогов и проверенных целей, не утверждение «все публичные предложения Москвы». Отдельные официальные и агрегаторные источники сравниваются только с сохранением роли источника и его снимка.
