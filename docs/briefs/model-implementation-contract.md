# Минимальный контракт: проверка кандидатов и проектный 3D

Дата решения: 2026-10-09. Реализуем утверждённый практичный гибрид из [концепта](../../reports/model-brainstorm/CONCEPT.md): индивидуальная модель появляется **после выбора проекта**, поверх постоянного городского ground. Это отдельный корпусный слой, а не замена `city_volumes`, не каталог квартир и не обещание точных фасадов. Текущий сайт/процессы не останавливать; новые активы публиковать версионно. Внешних покупок нет.

## Единица и offline-выход pipeline

Единица прохода — **исходная запись**, а не автоматически признанный ЖК или корпус. Текущий полный вход: 1473 принятых + 59 review EstateLine, 756 OSM-объектов `building=construction` и `construction=apartments|residential`, 27 сочинских жилых событий Минстроя + 2 московских упоминания газопровода. Итого **2317 входных записей**, а не 2317 уникальных московских новостроек. Синтетический devdb исключён. [Аудит входов](model-candidate-registry.md). Городские 564031 Overture контуров — подложка, не отдельные кандидаты этой проверки. Старые статусы EstateLine не становятся `observed_now`.

Каждая входная запись получает устойчивый opaque `candidate_id` с исходным namespace; ревизия источника не должна без причины менять её идентичность. `registry_id` допускает `null` и присоединяется только при доказанной связи, не по ближайшей точке или похожему названию. Выход: неизменяемый `data/models/<run_id>/assessments.jsonl` с **одной оценкой на каждую из 2317 записей**, отдельные проверяемые гипотезы связи, и `manifest.json` со `registry_snapshot_id`, input SHA-256/правами, `rules_version`, `checked_at`, counts scanned/ready/review/rejected/unavailable и SHA каждого JSONL. Повтор с теми же входами детерминированен; неполный run не заменяет активный. Приватная оценка хранит source IDs/URLs, даты, права, корпусный crosswalk, измеренные residuals и per-record `attempt_log`: какие строгие OSM-ID/address/point-overlap/part/donor проверки реально выполнялись и почему не дали проектную модель. Публичная проекция скрывает эти исходные данные по существующему server-side флагу.

Решения модели: `ready`, `review`, `rejected`, `unavailable`; отдельно `asset_readiness=ready_to_render|review|unavailable` и `project_link_status=verified|review|unlinked`. **Отклоняется модельная гипотеза, не ЖК**. `unavailable` означает отсутствие актива, а не отказ. `reason_codes` и безопасный русский текст объясняют `no_corpus_link`, `no_measured_geometry`, `unverified_location`, `outdated_version`, `rights_unconfirmed`, `crs_or_datum_unknown`, `conflicting_evidence`, `not_moscow_residential`, `non_building_infrastructure`, `source_unavailable`.

OSM-объект имеет самостоятельную source identity. Валидный полигон может иметь `asset_readiness=ready_to_render` с `entity_type=mapped_construction`, `registry_id=null`, `depiction=construction_outline` или `schematic_massing`, `geometry_quality=mapped_footprint|mapped_estimate`; он **не** становится утверждённым проектным корпусом или точным фасадом. Для массы нужна явная исходная высота либо отдельно обозначенная оценка render-height; без неё остаётся плоский контур. Подтверждённая связь с корпусом, проектная версия и соответствующие права обязательны **только** для утверждения, что геометрия представляет выбранный ЖК/корпус. Viewer, адресная точка, этажность, близкий Overture контур или AI-изображение сами этот gate не проходят. Публичный asset всё равно требует проверенных геометрии и прав на показ.

## Additive HTTP/схемы и UI

Существующие `/v1/registry/buildings`, `/v1/registry/map`, offer routes и city/ground descriptors сохраняют значения. Единый API для **всех 2317**: `GET /v1/models/candidates/summary`, `GET /v1/models/candidates?query=&decision=&reason_code=&source_group=&registry_id=&limit=&offset=`, `GET /v1/models/candidates/{candidate_id}` и on-demand `GET /v1/models/candidates/{candidate_id}/geometry` для пригодного к показу актива. List DTO: `candidate_id`, nullable `registry_id`, `name`, generic `source_group`, `entity_type`, `decision`, `asset_readiness`, `ready_to_render`, `project_link_status`, `depiction`, `geometry_quality`, `reason_codes`, `explanation_ru`, `next_step_ru`, `geometry_as_of`, nullable `render_height_m` и раздельные mapped-height/levels/estimated-render-height evidence. **List не содержит asset URL/GLB и подробных попыток**; выбранный detail может показать до 8 безопасных результатов строгих проверок из allowlist, geometry выдаётся только по выбору. `summary` содержит `model_run_id`, `registry_snapshot_id`, `checked_at`, denominator 2317 и распределение решений. Geometry возвращает verified center/bbox и выбранный полный Polygon/MultiPolygon preview с отверстиями (у 756 OSM максимум 277 координатных пар, лимит 512 без обрезки) + immutable sanitized URL и атрибуцию. Провайдерские имена и внутренние пути скрыты существующим server-side флагом; обязательная ODbL-атрибуция сохраняется. Активный run выбирается только после проверки manifest/hash/count. Public API валидируется ETag/304; без проверенного run summary отвечает 503, а не ложным нулём. Source-exposed mode — `no-store`; versioned assets — immutable/compat.

Web `/models` показывает по умолчанию отклонённые кандидатуры, фильтры и причины **по всему входу**, не удаляя проекты из реестра. Самостоятельный OSM-контур показывает его mapped-estimate уровень; связь с ЖК заявляется только при `project_link_status=verified`. При выборе подтверждённого проекта web запрашивает модель on-demand, сохраняя ground-first, адаптивный frame gate, 12/16-км guard и кэш; non-ready показывается причиной/неизвестностью вместо ложного 3D. Native DTO принимает новые поля аддитивно; текущий native registry остаётся явно unsupported, не подставляет demo.

## Обязательная проверка выпуска

Offline: каждая из 2317 source rows оценена ровно один раз; причины для всех non-ready; OSM-ready без `registry_id` разрешён, но project claim только с verified link; public URL только при geometry+rights; old registry 1473/10/0 offers не искажён; приватные ID/URL не утекли; geometry bounds/CRS/holes/атрибуция, размер и LOD проверены; повторный run стабилен. In-process API/schema тесты и web pure tests/build обязательны. Текущий sandbox не доказывает live HTTP, браузерный FPS, Unity Editor или iPhone; эти границы фиксировать отдельно. Никакой покупки или сообщения правообладателю в этой реализации не требуется.
