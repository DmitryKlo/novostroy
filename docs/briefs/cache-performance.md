# Web cache and map loading audit

**Исторический baseline до изменения web-кода.** Описания размонтирования Viewer, повторных `/v1/map` и отсутствия явной cache policy ниже относятся к прежней реализации; они не описывают текущий v6-клиент. Фактически принятые изменения и проверки приведены в [README](../../README.md) и [validation report](../../reports/validation.md). Срез исходников: 2026-10-09. Это аудит кода и план измерения, не результат браузерного замера. При проверке `scripts/dev.py status` оба управляемых процесса (`api`, `web`) были остановлены. Sandbox запрещает локальные TCP bind/connect с `EPERM`; поэтому preview не запускался и сетевой baseline не снимался. Не считать эту запись результатом iPhone/Safari или Chromium.

## Что сейчас делает карта

- `MapView` создаёт Cesium `Viewer` один раз на mount, включает `requestRenderMode`, отключает рендер по таймеру и ограничивает эффективное разрешение примерно 1.5 пикселя на CSS-пиксель. Это снижает работу в простое и fill-rate, но само по себе не ограничивает сетевую загрузку. `requestRenderMode` пропускает кадры, пока нет render request или движения камеры; запросы 3D Tiles идут по выбору тайлов.
- На старте камера ставится примерно на 5.2 км. После получения map data выполняется полёт к выбранной демо-модели на 800 м за 1.3 с; выбор ЖК переводит к 470 м. У Cesium 1.134 default `preloadFlightDestinations` включён, поэтому destination tiles могут запрашиваться во время полёта. У city SSE 24, у фасадов 8; более низкий SSE требует больше детализации. У 3D Tilesets также включены стандартные dynamic/foveated SSE и progressive-resolution traversal.
- На текущем снимке карта получает семь наборов: city v5, roads, parks, water и три синтетических фасада. `MapView` выделяет общий номинальный cache budget 128 MiB для ширины до 700 px и 160 MiB иначе, вычитает overflow 2 MiB на набор, затем распределяет остаток по весам (city 11, дороги 2, фасад 0.25, прочие 1). Это бюджет Cesium tile cache, а не измерение всего RSS/GPU и не браузерный HTTP cache.
- Локальный корневой `assets/public-citywide-v5/tileset.json` занимает 3.4 MiB до gzip. Сервер сжимает обычные ответы от 1 KiB, так что фактический wire size может быть ниже, но ни wire bytes, ни JSON parse time в этой среде не измерены. Иерархия GLB загружается дальше по видимым тайлам.
- На изменение фильтров React обновляет entities и сравнивает набор URL слоёв. Не изменившиеся URL сохраняют объект Cesium и его tile cache. Фасад, исчезнувший из фильтрованного ответа, удаляется из primitive collection и уничтожается; если он появится снова, для URL создаётся новый Cesium tileset. Городские URL остаются общими между фильтрами.
- Мобильная кнопка «Квартиры/Карта» только скрывает колонку CSS-классом; она не размонтирует viewer. Вкладка «Данные» заменяет весь `app-grid`, поэтому `MapView` размонтируется: cleanup очищает `tilesRef` и уничтожает viewer. Камера сохраняется в JS-модуле, но Cesium/GPU tile cache теряется. При возврате viewer создаётся заново и запрашивает слои снова. Сам отчёт «Данные» сохраняется отдельно в памяти модуля на время жизни страницы.

## Повторные запросы приложения

Первичная загрузка делает `GET /v1/health`, `/v1/map`, `/v1/districts`, `/v1/criteria` параллельно. После установки `health` effect запускает поиск и рекомендации, затем ещё один `GET /v1/map` по применённым фильтрам. Для пустого начального поиска этот map-запрос обычно совпадает с первым: `limit` не сериализуется в query string. Это повторный расчёт API; точные URL и кратность следует подтвердить baseline после восстановления preview.

Каждый отправленный поиск делает два uncached по коду `POST` запроса — `/v1/search` и `/v1/recommendations` — и затем отдельный `GET /v1/map`. `api.ts` вызывает обычный `fetch` без memoization, abort, Cache API или заданной cache policy. Ответ карты содержит те же дороги/парки/воду и городские URL, но создание нового объекта `data` всё равно запускает effect и пересобирает marker entities. Текущие URL позволяют повторно использовать уже живые Cesium tilesets; переход на вкладку «Данные» этого преимущества лишает.

`DataDashboard` уже имеет in-memory cache ответа `/v1/data-coverage` в пределах текущей SPA-сессии. Избранное отдельно делает GET для каждого сохранённого offer при открытии/изменении списка; это не причина перезагрузки 3D Tiles.

## HTTP cache и диапазонные запросы

`RenderAssetFiles` допускает только `tileset.json` и `.glb` из фасадов, текущих public asset roots и предыдущих public roots, у которых подтверждён `public_redacted_source_ids`. Поэтому старый city v4 остаётся доступен как sanitized compatibility root; manifest указателя сам через этот mount не выдаётся. Vite dev и preview просто проксируют `/v1` и `/assets` в API.

Для обычных `/assets` в установленном preview-окружении (FastAPI 0.143.0 / Starlette 1.7.0) `StaticFiles`/`FileResponse` выставляют `ETag`, `Last-Modified` и `Accept-Ranges: bytes`; `StaticFiles` умеет ответить 304 на `If-None-Match`/`If-Modified-Since`. Приложение не задаёт `Cache-Control`, так что срок свежести остаётся эвристикой браузера. ETag Starlette основан на mtime и размере файла, а не на digest содержимого; версию опубликованного набора надёжнее закрепляет URL. Для API JSON `Cache-Control`/ETag в обработчиках не добавлены. `RangeSafeGZipMiddleware` сжимает обычный ответ от 1024 байт, но пропускает `Range`/`If-Range` и `HEAD`; Starlette FileResponse поддерживает 206 и `Content-Range`. Это подтверждает серверную возможность Range, но не доказывает, что Cesium делает Range-запросы для этих GLB. Живые HTTP-заголовки не сняты.

Имена путей публичных city/road/park/water наборов включают версию, поэтому для них годовой `public, max-age=31536000, immutable` допустим при условии, что опубликованная версия после выдачи URL не перезаписывается. Старый v4 должен сохранять те же права на неизменяемый кэш, пока URL его версии остаётся прежним. Фасады используют стабильные `/assets/facades/...` пути: до введения версии/хэша на каждый выпуск для них безопаснее короткий срок и revalidation. Workers/Assets Cesium копируются под `/cesium` с постоянными именами; долгий immutable cache для них безопасен только если URL также включает версию Cesium/сборки.

## Рекомендуемый порядок изменений

1. Сначала добавить и измерить кэширование версионированных публичных tile paths. Не кэшировать изменяемый manifest/API надолго. Для фасадов либо ввести versioned path, либо оставить revalidation. Для изменяемого URL проверить, что смена содержимого даёт новый validator; не считать ETag Starlette content hash. Отдельно проверить gzip/range и валидаторы.
2. Устранить совпадающий начальный `/v1/map` через in-flight/result dedup по `snapshot_id + нормализованным filters`; сохранять текущие проверки, что карта и поиск относятся к одному snapshot. Не кэшировать произвольные POST и не оставлять старый map response после обновления snapshot.
3. Снизить лишнюю работу при переходах вкладок: решить отдельно, допустимо ли удерживать скрытый viewer в памяти телефона. Если viewer размонтируется ради освобождения WebGL памяти, HTTP cache immutable URL должен сделать повторный сетевой путь дешёвым. Не держать одновременно весь city GLB набор в Cache API.
4. Для «силуэты сначала, детали потом» измерить отдельные фазы старта и полёта. Сравнить `preloadFlightDestinations` включён/выключен и более грубый SSE для city massing, а точную детализацию оставить для близкого вида/выбранного ЖК. Не менять оба фактора в одном сравнении и отдельно проверить качество кадра после остановки камеры.
5. Service Worker сейчас не нужен для ускорения повторных online открытий: HTTP cache подходит для versioned immutable tiles и управляется браузером. Добавлять SW только при явном offline-требовании. Если оно появится, держать ограниченный LRU для реально посещённых tiles, кэшировать manifest отдельной версией, удалять старые cache namespaces и учитывать `navigator.storage.estimate()`; не precache всего города.

## Воспроизводимый замер

`.runtime/cache-baseline.mjs` — узкий QA harness для существующего preview, не продуктовый код. Он открывает только `http://127.0.0.1:5173/?__map_test=1` в Chromium с viewport 390×844, DPR 3 и touch emulation без подмены user-agent, делает cold navigation и затем reload той же страницы в том же контексте. На обеих фазах он ограничивает ожидание сетевой тишины 20 секундами, пишет запросы по скрытым стабильным ключам, Resource Timing, HTTP status/cache headers, Cesium tile-cache metrics и сводку интервалов между render кадрами. Используется одна страница без screenshot/trace; лимиты Cesium остаются текущими (128 MiB cache плюс per-layer overflow). Это не жёсткий RSS cap: browser process memory не измеряется и в текущей sandbox прогон не выполнялся. Запускать только когда preview уже доступен: `rtk proxy node .runtime/cache-baseline.mjs`. Результат сохраняется в `.runtime/cache-performance-baseline.json`.

Этот режим строго маркируется как Chromium mobile-viewport emulation. Он не является WebKit, Safari или физическим iPhone замером. Текущий baseline: **не снят**, поскольку managed preview был остановлен, а локальный TCP заблокирован sandbox; после сообщения root дополнительные сетевые попытки не выполнялись. Для вывода о Safari нужен отдельный запуск на физическом iPhone или явно доступном Safari/WebKit стенде с тем же URL и геометрией.
