# Ново · веб-каталог

React, TypeScript и CesiumJS. 3D Tiles и данные приходят с локального FastAPI. Ключ Cesium ion или платная базовая карта не нужны: сцена использует эллипсоид и локальные 3D-объекты.

Из корня репозитория сгенерируйте демо-каталог и 3D Tiles, затем запустите API:

```bash
rtk python -m pipeline.generate_demo
rtk python -m pipeline.build_tiles
rtk uvicorn backend.app:app --host 0.0.0.0 --port 8000
```

Во втором терминале:

```bash
cd web
rtk npm install
rtk npm run dev
```

Откройте `http://localhost:5173`. Для iPhone в той же сети откройте `http://<LAN-IP-компьютера>:5173`. Vite слушает `0.0.0.0:5173` с `strictPort`; `/v1` и `/assets` проксируются на `127.0.0.1:8000` на компьютере. Сервер API должен работать одновременно с Vite. Для просмотра собранной версии используйте `rtk npm run build`, затем `rtk npm run preview`: production preview применяет тот же прокси. Запуск через HTTP допустим для локального просмотра; доступность зависит от правил сети и межсетевого экрана.

Дополнительные фильтры строятся из `/v1/criteria` v1.1. Числовые пороги, варианты и трёхпозиционные логические условия являются строгими: отсутствие подтверждённого значения не считается совпадением. Карточка показывает числовые факты, дату и статус; реестр сам по себе не означает, что поле заполнено у каждой квартиры.

Вкладка «Данные» загружает один агрегированный отчёт `/v1/data-coverage` и отдельно показывает учебные предложения, текущие реальные предложения и городские контуры. Заполненность поля означает наличие значения с указанным качеством; иллюстративные и оценочные величины не становятся наблюдениями. Графики цены и площади относятся только к выбранному набору предложений. События `/v1/metrics` здесь не используются.

Проверки: `rtk npm run build` и, при работающем API, `rtk npm run test:e2e`. Тест делает снимки экрана в `web/test-results/`. Отдельный `rtk npm run test:webkit` проверяет движок Safari, если на хосте доступны системные библиотеки Playwright WebKit. Проверка в Linux Chromium с мобильным размером окна не заменяет тест на iPhone. Демо-данные, фасады и цены схематичны; экран постоянно обозначает демо-режим и происхождение каждого предложения.

Когда импортированный реестр зданий включён на API, он становится основным каталогом. Поиск и фильтры по статусу и типу применяются одним запросом к списку и карте. Карта отмечает только записи с подтверждённой геопривязкой; остальные остаются в списке. Карточки показывают доступные сведения о здании и явно обозначают отсутствие данных о квартирах и ценах. Вкладка «Данные» показывает покрытие реестра и городской геометрии.

Новый режим `catalog_view=developer_buildings` использует один опубликованный снимок корпусов, полученных из снимков квартир, для списка, карты и `/v1/map/points`. Он полностью заменяет прежние точки `building_registry` и `mapped_construction` в видимой карте; фоновые городские 3D Tiles остаются. В карточке корпуса и выбранной точки показаны адрес (с отметкой частичного адреса), ЖК и застройщик. Меню выбранного дома загружает секции, этажи и квартиры по запросу. Цена подписана датой снимка и не означает текущую цену или наличие. Фильтры цены, цены за м², комнат, площади и этажа применяются к одной квартире во всех трёх ответах каталога, списке этажей и меню дома до пагинации; этажи без подходящих квартир не показываются, а полный список открывается только по явному действию. Статус, сроки сдачи и общая этажность не фильтруются без подтверждённых полей. Ответы списка, карты и точек должны совпадать по `registry_snapshot_id`/`snapshot_id`, `map_run_id` и `unit_run_id`; при смене снимка клиент сбрасывает выбранные точки и кэш объектов рядом. Группы ЖК создаются только по явному свидетельству общего идентификатора. На карте маркеры появляются лишь над уже загруженной геометрией. Выбранная реконструкция корпуса загружается отдельно и не скрывает остальные городские объёмы: ими по-прежнему управляет адаптивная стадия качества. Текущие городские тайлы не содержат идентификаторов отдельных зданий, поэтому совпадающий с реконструкцией фоновый объём пока нельзя исключить точечно. Если для этажа опубликован точный план, пять анонимных областей пилота показываются как условный объём по изображению: они не связываются с квартирой или ценой без проверенного соответствия. Вкладка «Данные» использует `developer_building_registry` и не смешивает его с прежним реестром или демо-предложениями.

Дополнительный слой карточек привязан к `enrichment_run_id`: его смена сбрасывает клиентский каталог и выбранные детали даже при неизменном снимке домов. Округ и максимальный индекс шума фильтруют дома, этажи и квартиры только после явного выбора; неизвестный шум не считается нулём. Оценка шума подписана «Внутренняя оценка платформы». Для воздуха показываются PM2.5, PM10 и NO₂ лишь вместе с датой, пометкой «Модельная оценка» и атрибуцией Open-Meteo / CAMS Europe; отсутствие модели отображается прочерком. Маршрут до границы парка подписан как пеший, без утверждения о проверенном входе. Фотография конкретного ЖК и планировка конкретной квартиры загружаются только по привязанным к ним media ID; при сбое источник не подменяется другим изображением.

После переключения работающего API выполните из `web/` `rtk node scripts/check-developer-live.mjs http://127.0.0.1:5173` и `rtk node scripts/check-developer-experience-live.mjs http://127.0.0.1:5173 --require-enrichment`. Скрипты не запускают сервер и сохраняют JSON-отчёты и снимки настольного и мобильного Chromium в `.runtime/browser-developer-live/` и `.runtime/browser-developer-experience-live/`. Второй проверяет реальную фильтрацию списка, карты, точек и меню квартир, план этажа, выбранную текстурированную модель, загрузку и декодирование фотографии ЖК и плана квартиры. Флаг `--require-enrichment` требует опубликованного нового слоя данных и запрещает принять старый ответ без него. Для staged-артефактов до публикации: `rtk proxy npx playwright test tests/developer-experience-stage.spec.ts --project=desktop --project=mobile`. Физический iPhone проверяется отдельно.

Для внешнего HTTPS-развёртывания передайте обоим live-скриптам публичный origin, например `rtk node scripts/check-developer-live.mjs https://79.141.74.15` и `rtk node scripts/check-developer-experience-live.mjs https://79.141.74.15 --require-enrichment`. Сертификат HTTPS проверяется обычным образом. Эти проверки читают только ответы развёрнутого API и браузерные ресурсы: локальный staged-fixture им не нужен. Первый проверяет также корневые JSON всех городских tileset и отсутствие HTTP-ошибок у фактически загруженных тайлов/подготовленных assets, маршруты и отсутствие повторных станций метро. Второй открывает дом, этаж, квартиру, исходный план, выбранный GLB и дом без модели, проверяя по публичному интерфейсу видимую реконструкцию, сохранение карты без модели и последовательный Escape. Точное состояние `city_volumes` доступно тесту только на `127.0.0.1`: в публичной сборке диагностический хук карты намеренно отключён. Отчёты и снимки остаются на машине, где запущен скрипт. Staged Playwright-тест использует локальные `.runtime`/`data` assets и для внешнего сайта не предназначен.

Публичная проверка развёртывания исходной версии `313f9b2` 10 октября 2026 года прошла на настольном и мобильном Chromium: [карта и каталог](../.runtime/browser-developer-live/2026-10-10T22-20-31.206Z/report.json) и [меню дома, квартиры и модель](../.runtime/browser-developer-experience-live/2026-10-10T22-20-31.206Z/report.json). Ответы показали 1163 корпуса и 1027 точек одного снимка; оба теста завершились успешно, без ошибок консоли и HTTP-ошибок загруженных ресурсов. Снимки экрана лежат рядом с отчётами. Это браузерная проверка, не испытание на физическом iPhone.

На узком экране карта оставляет место над нижней навигацией; выбранный корпус показывает адрес, ЖК, застройщика и дату в карточке. Панель «Рядом на карте» изначально свёрнута и раскрывается по нажатию, чтобы не закрывать точку и геометрию.

В режиме реестра `/v1/map/points` отдаёт компактный набор точек независимо от пагинации списка: записи зданий с подтверждённым адресом и отдельные картографические контуры строек. Общие query/status/kind фильтры применяются к списку и точкам; status/kind не сопоставляют поля реестра с картографическими стройками и явно исключают их. Легенда показывает количество записей с координатами и зданий текущей выборки без подтверждённой точки. Совпадающие координаты не объединяют источники: карточка одной позиции позволяет выбрать обе записи отдельно. Нажатие на картографическую точку показывает только краткие сведения и ссылку на её оценку; оно не загружает геометрию кандидата или индивидуальный 3D tileset. Подпись появляется лишь у выбранной точки. Кнопка «Показать все новостройки» подгоняет камеру по фактическим точкам; обновление фильтра само не перемещает камеру. Точечная карточка показывает только адрес и подпись ЖК, полученные из конкретной записи или её точной связи с родительским контуром; совпадение координат не создаёт связь с каталогом. Картографические стройки отмечены более приглушённым оттенком терракотового и не считаются подтверждёнными корпусами ЖК или полным перечнем новостроек Москвы. При наличии таких точек карта сохраняет `© OpenStreetMap contributors; ODbL 1.0`.

Слои метро, школ и детсадов, медицины изначально выключены: карта не запрашивает и не рисует POI при открытии. Выбор любой точки с подтверждёнными координатами включает три слоя и запрашивает `/v1/map/nearby` только для её `point_id`: не более пяти объектов каждой категории и отдельный статус пешего маршрута для каждого. Фильтр образования выбирает школы, детсады или оба типа. Пять медицинских записей могут включать одну подтверждённую клинику ОМС вместо пятой ближайшей по прямой; карточка объясняет это, а отсутствие подтверждения не означает отсутствие бесплатной помощи. Время показывается только при маршруте по локальному пешеходному графу и остаётся приблизительным временем от точки на карте, не от установленного входа в дом. Маршрут к метро может закончиться у связанного с ним нанесённого входа, при этом значок станции не подменяется входом. Без выбранной новостройки категории можно включить вручную для видимого участка: `/v1/map/nearby/viewport` ограничен областью до 0,15° по каждой оси и 150 точками суммарно, без расчёта маршрутов; на общем обзоре интерфейс просит приблизить карту. Смена точки, фильтра и вкладки отменяет устаревшие запросы; краткий клиентский кэш ограничен временем, количеством записей и объёмом. При закрытии выбранной точки автоматически включённые слои и маршруты исчезают.

`MapView` остаётся смонтированным при переходе на вкладку «Данные» и хранит Cesium tilesets, камеру и текущий кэш тайлов в пределах вкладки браузера. Скрытая карта останавливает render loop; при возвращении выполняется resize и запрашивается кадр. Фасады, временно скрытые фильтром, удерживаются в кэше максимум по три; общий номинальный бюджет Cesium остаётся 128 MiB на мобильном экране и 160 MiB на широком, включая по 2 MiB overflow на набор. `/v1/map` дедуплицируется по нормализованному URL в пределах снимка каталога, максимум 12 результатов. Статические версионированные пути `/assets/public-*` кэширует браузер по заголовкам API. Service Worker не требуется.

Когда API передаёт отдельный слой `ground_buildings`, карта сначала запрашивает только плоскую основу: контуры зданий, дороги, парки и воду. Городские объёмы и фасады даже не создаются через `fromUrl`, пока видимый точный контент ground (геометрическая ошибка не более 2 м) не пройдёт два завершённых кадра `postRender` при одной камере и размере canvas, а корни остальных плоских слоёв не будут подключены либо не вернут ошибку. Детальная подгрузка дорог, парков и воды не задерживает объёмы. Для road-v2 общий обзор оставляет крупные дороги: точные дорожные ячейки допускаются только при высоте камеры до 1 км, после остановки движения и на проверенной плавной стадии клиента; при удалении на 1,5 км возвращается крупный уровень. Дорожный tileset и его кэш при этом сохраняются, а невидимые соседние ячейки не подгружаются через skip LOD. Это барьер фактически видимой подложки, а не ожидание корневого JSON или задержка по таймеру. Ground остаётся под объёмами отдельным постоянным tileset с SSE 2; для него включён Cesium skip LOD без загрузки невидимых соседних регионов. Для городского v8 и более новых наборов объёмы и детали загружаются после барьера без сброса SSE при движении камеры. При отдельном ground городские объёмы запрашиваются только ниже 12 км высоты камеры и скрываются выше 16 км; между порогами действует гистерезис. Дальний обзор показывает постоянную плоскую карту, а уже загруженный 3D tileset сохраняется в кэше для возврата. Фасады этим порогом не затрагиваются. Скрытие карты останавливает render loop, но не удаляет сцену и слои; при возвращении выполняются resize и кадр. Поздний ответ от уничтоженной сцены не присоединяется к новому Viewer. Счётчик «подключено» относится только к корням tileset текущего масштаба; сбой вложенного GLB показывает отдельное постоянное предупреждение, а диагностика `failedLayers()` сохраняет URL, тип и текст ошибки Cesium.

Объёмы и фасады включаются по замеренному на данном клиенте запасу плавности. После готовности плоской карты ограниченная проба запрашивает кадры и измеряет интервалы между активными `postRender`; обычные паузы в режиме `requestRenderMode`, скрытая вкладка и движение камеры не дают ложного допуска к деталям. Два здоровых окна повышают качество по ступеням: плоская карта → укрупнённые объёмы (SSE 128) → объёмы SSE 64 → детали SSE 24 и фасады. Длинные кадры понижают качество или временно оставляют только плоскую карту; тот же вид не пробуется без конца, а новый значимый ракурс или завершение начальной загрузки даёт ограниченный повтор. Загруженные tileset при понижении качества сохраняются. Эта политика действует и для старых карт без отдельного ground. `__novoMapTest.adaptiveQuality()` сообщает стадию, причину, число окон, p75 активных интервалов и состояние ограниченной пробы. Это оценка отзывчивости по кадрам, а не измерение GPU-времени или гарантия FPS.

Старые городские v6/v7 без отдельного ground продолжают использовать прежнюю ступенчатую загрузку региональных силуэтов; v7 дополнительно хранит детальные поддеревья в региональных JSON. Этот путь определяется по точному публичному URL. Проверка логики без сервера: `rtk npm run test:unit`. Пока browser preview недоступен, визуальная готовность и FPS не подтверждены.

Экран `/models?decision=rejected` показывает оценки моделей из общего API `/v1/models/candidates`, включая отклонённые записи с причиной, следующим шагом и деталями проверенных путей восстановления «Что проверено». Он использует итог `/summary`, фильтры решения, причины, группы и поиска, серверную пагинацию по 24 кандидата и сохраняет состояние в URL при обновлении и переходах назад/вперёд. Кандидаты без связи с ЖК явно помечены; ссылка «Проверить модели» у выбранного здания ограничивает список проверенным `registry_id`, не приписывая ему самостоятельные картографические контуры. «Можно показать» включает плоские контуры и отдельно подсчитанные оценочные объёмы. При старом API или ещё не опубликованном проверенном запуске экран показывает ошибку и повтор, а не пустой список.

Список не получает адреса файлов моделей. Только после выбора кандидата запрашиваются detail и его геометрия; поздние запросы отменяются при смене выбора, а detail и geometry показываются лишь при совпадении candidate ID и run. Проверенный контур сразу показывается как лёгкий SVG по selected-only GeoJSON `preview_geometry`, включая отдельные полигоны и отверстия (`evenodd`); прямоугольник охвата не подменяет контур. Для плоского контура при неизвестной высоте WebGL вообще не создаётся. Если оценочный объём имеет конечную положительную `render_height_m`, отдельный Cesium Viewer загружает только выбранный tileset после видимого плоского кадра и ограниченной пробы активных кадров. Общие `city_volumes` и фасады в этом просмотре не подключаются. Проба измеряет интервалы кадров как приближение отзывчивости клиента, а не GPU-время или гарантированный FPS. Скрытие просмотра останавливает render loop и сохраняет уже загруженный набор до смены выбранного кандидата. Юнит-проверка маршрута, фильтров, кэша и строгого допуска 3D: `rtk npm run test:unit`; сборка: `rtk npm run build`. Живой браузер и физический телефон этим не проверяются.

После появления доступного managed preview с активным реестром измерьте cold/warm в одном контексте Chromium: из `web/` выполните `rtk npm run measure:cache`. Скрипт использует только `http://127.0.0.1:5173/`, viewport 390×844, DPR 3, на обеих фазах открывает вкладку «Карта», ждёт сетевой тишины не дольше 35 секунд и сверяет конечную камеру. Отчёт сохраняется в `.runtime/cache-cold-warm-ground-v8.json`: количество и объём запросов реестра, ground и городских тайлов по хэшированным ключам, HTTP cache headers, Resource Timing, память Cesium, кадры ground и фактически видимые объёмы. При демо-каталоге скрипт завершается без отчёта. Это эмуляция Chromium, не замер Safari или физического iPhone. Если `sameCamera=false` или `idleTimedOut=true`, сравнение не годится для вывода об ускорении.
