# Combined source-point map contract (v1.3)

`GET /v1/map/points` is additive to `/v1/registry/map` and `/v1/models/candidates`. It returns every eligible source-backed point for the current validated registry/model snapshots, independently of the 48-row registry list page. It contains point metadata only: no model URL, mesh, outline, height, offer, or inferred project link. The initial local/internal snapshot has 10 strictly address-verified registry points and 756 representative points from valid OSM construction polygons, totaling 766 source records at 765 coordinate positions. This is not a count of unique housing complexes or present-day construction sites. The 1,463 accepted registry records without verified coordinates stay off the map.

Each `MapPoint` has an opaque stable `point_id` and exactly one typed target: `point_type=registry` with `registry_id`, or `point_type=mapped_construction` with `candidate_id`. The exact cross-source coordinate overlap stays as two selectable records because no project identity link is verified. Marker selection first opens a lightweight point card; the separate model-review link is an explicit user action. The point route itself never requests selected geometry.

The additive `address` and `complex_label` are nullable and each has an explicit `*_basis`. A registry point uses its own internal-use source address and name; `known_catalog_registry_id` equals its confirmed opaque registry identity. An OSM point may carry a source street/house or place address and a direct OSM ЖК name, `addr:place`, or named parent-relation label. Those source labels are **not** a registry/EstateLine crosswalk, so `known_catalog_registry_id` stays null for every mapped-construction point. Missing source fields stay null; no nearest-neighbour address or project name is borrowed.

`query` searches displayed names in both groups. `status` and `kind` apply to registry records only; mapped-construction records have neither fact, so they are excluded and `counts.excluded_mapped_by_registry_filters` reports how many query-matching mapped points were excluded. `counts.points`, group counts, and `coordinate_positions` are filtered; `dataset_total` and `counts.registry_points_total` are unfiltered. Invalid `kind` returns 422. The response carries `registry_snapshot_id`, `model_run_id`, dates, `registry_rights_status=user_supplied_internal_use`, and required OSM attribution. In the existing authorized local/internal mode, registry rights do not become a new open/public redistribution license. The private mixed response uses a weak ETag with `private, max-age=0, must-revalidate`; source-exposed mode is no-store.

The full JSON Schema is `schemas.json#/$defs/MapPointsResult`; the route and query parameters are in `openapi.json`. Native DTOs are additive source compatibility only: native registry browsing remains explicitly unsupported rather than falling back to demo offers. Browser and device rendering must be checked after the managed host API is restarted; direct route tests do not prove those environments.
