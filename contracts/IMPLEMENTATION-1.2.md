# Model candidate review contract (v1.2)

`openapi.json` and `schemas.json` define one additive `/v1/models/candidates` API. The assessment unit is a **source record**, not a unique legal building: the first pinned run scans 1,473 accepted and 59 review EstateLine records, 756 OSM residential-construction polygons, and 29 Minstroy audit events (27 Sochi, two Moscow gas-pipeline mentions). These 2,317 records never become 2,317 claimed Moscow complexes. An absent or incomplete validated run returns 503; it does not report zero coverage.

Every row has an opaque, stable `candidate_id`; `registry_id` is nullable. A source-backed OSM polygon may be `decision=ready` and `asset_readiness=ready_to_render` with `entity_type=mapped_construction`, `project_link_status=unlinked`, and `depiction=construction_outline`. Its independent OSM identity permits an appropriately attributed mapped outline, but does not prove current construction, a project/corpus match, a licensed architectural facade, or an approved plan. A confirmed project model requires an independently verified link, geometry/version checks, and display rights. A height inferred solely to render a mesh is labeled as an estimate; unknown sizes remain unknown.

`GET /v1/models/candidates/summary` reports the validated run, counts, and facets. The paginated list supports search, decision, reason, generic source group, and exact `registry_id` filters. The list contains no geometry URL, GLB data, or per-gate attempt detail. Detail supplies the public explanation, optional allowlisted Russian attempt results, and optional asset reference; `/{candidate_id}/geometry` supplies bounded selected Polygon/MultiPolygon preview with closed rings and holes, plus immutable sanitized tileset metadata only for renderable candidates. `ready`, `review`, `rejected`, and `unavailable` are distinct. A rejected **model hypothesis** does not remove a registry building; a missing asset is `unavailable` rather than rejected. The selected-project web flow uses exact `registry_id` filtering and claims a project model only when `project_link_status=verified`.

Public provider identities, internal IDs, raw tags, file paths, and provenance URLs remain hidden by the existing server-side flag. Required ODbL map attribution remains visible. A public sanitized response can use ETag/304 revalidation; source-exposed mode is `no-store`. Published geometry is immutable and versioned. The mobile source has additive DTOs but still explicitly does not support registry browsing or model review; it never substitutes demo offers.

The selected `preview_geometry` preserves complete source rings for this pinned OSM corpus: all 756 fit within 512 coordinate pairs (maximum 277), including 18 multipolygons and 11 courtyards absent from the older 128-point outer-ring preview. It is never arbitrarily truncated. The older nullable `footprint` remains for compatibility but must not be used to fill a holed polygon.
